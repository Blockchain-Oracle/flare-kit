OperationTimeline

Renders a durable operation as actor-owned steps. It survives reload, names who is being waited on at every stage, and treats a partial outcome as a destination rather than an error.

import { OperationTimeline } from "@flare-kit/react"

Mock by default. Every example on this page runs against an in-memory operation. No wallet, no chain, no testnet funds. Swap mockKit for config to go live.

import { OperationTimeline } from "@flare-kit/react"

export function MintStatus({ id }) {
  return (
    <OperationTimeline
      operationId={id}
      showEvidence
      onRecover={(action) => track(action.id)}
    />
  )
}

Illustrative fixture. A design-only state change is not protocol evidence.

Usage

Wrap once at the root, then render the timeline anywhere. The component subscribes to the operation record, so it recovers its own state after a reload.

app.tsx
<FlareProvider config={config}>
  <OperationTimeline operationId="op_01J4FX9K3R7N" />
</FlareProvider>

Props

PropTypeDefaultDescription
operationIdstringrequiredDurable operation to render. Deep-linkable.
showEvidencebooleantrueShow copyable chain identifiers per step.
onRecover(a: RecoveryAction) => void—Called when a recovery action is chosen. The component never signs.
compactbooleanfalseOperator density: tighter rows, no card chrome.
localestringhostFormats dates and numbers. Exact onchain values stay unformatted.

States

The component renders from a discriminated operation status. Every state below is reachable in the gallery above and in the test suite.

  • draft intent captured, nothing submitted
  • awaiting_external a named third party owes the next move
  • action_required you owe the next move
  • partially_succeeded value moved, outcome incomplete
  • succeeded terminal, with finality named
  • failed terminal, nothing recoverable
  • unknown outcome not confirmed yet, never shown as failure
