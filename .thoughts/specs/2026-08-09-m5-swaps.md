## Objective

After this milestone a developer can install the kit and drop a working token
swap into their own React app, and a person can swap real tokens through a real
DEX on Coston2 — testnet first — seeing an **honest quote** from live pool
reserves, the **exact minimum received** under their slippage, the real approval
and swap as two steps, and the transaction on an explorer. Swap is the first
application-layer capability built on top of the FAssets/FTSO/FDC primitives, and
it reuses the durable operation lifecycle M1 forced into being.

## The venue — decided, and what is verified first

The kit integrates the **Uniswap V2 router *interface*** (not a brand), with the
router and factory addresses coming from `@flare-kit/contracts` per network —
**BlazeSwap on Coston2**, BlazeSwap or SparkDEX's own V2 router on mainnet. The
reasoning is in the research doc; in short, it is the only path that satisfies
**network is configuration** (BlazeSwap's V2 AMM is live on both Coston2 and
mainnet; SparkDEX's V3 AMM is mainnet-only in its docs), and V2's `getAmountsOut`
gives an honest one-call quote with no separate quoter and no tick math to get
wrong.

Known mainnet references (from Flare's developer-hub + SparkDEX docs): SparkDEX
V2 Router `0x4a1E5A90e9943467FAd1acea1E7F0e5e88472a1e`, BlazeSwap Router
`0xe3A1b355ca63abCBC9589334B5e609583C7BAa06`, FXRP resolved from the Asset
Manager, USDT0 `0xe7cd86e13AC4309349F30B3435a9d337750fC82D`.

**Grounded by the R1 probe (`.thoughts/verification/2026-08-09-m5-r1-coston2-swap-venue.md`):**
on Coston2 the BlazeSwap deployment holding FXRP liquidity is Factory
`0x02d03957Cf02d153141bf23C60099E9aa48bf872` / **Router
`0x440602f459d7dd500a74528003e6a20a46d6e2a6`** (a *second* BlazeSwap deployment
exists but has no FXRP pool — use this one). The one FXRP pool is **FXRP / USD₮0**
(`0xDD598473…`), NOT FXRP/WCFLR (`getPair(FXRP, WNAT)` is zero) — the demo pair is
**USD₮0 ↔ FXRP**, matching mainnet. Coston2 tokens: FXRP `0x0b6A3645…` (6 dp),
USD₮0 `0xC1A5B41512496B80903D1f32d6dEa3a73212E71F` (6 dp), WNAT
`0xC67DCE33…` (18 dp). A live quote returns (`getAmountsOut(1 FXRP)` → 1.224 USD₮0),
so the venue is real — but the pool is thin and untraded, so the surface renders
price impact honestly, and a deep demo can run mainnet on the same code path.

## Requirements

- **M5-R1 — On-chain venue probe, first (real-first).** Before the surface is
  written, a live probe on Coston2 establishes: the BlazeSwap Router + Factory
  are deployed (code present); which FXRP-paired pools exist (FXRP/WCFLR,
  FXRP/USDT0, WCFLR/USDT0) via `factory.getPair`; and each pool's real reserves
  via `pair.getReserves`. The results are recorded as evidence and the addresses
  written into `@flare-kit/contracts`. **If no Coston2 pool holds swappable
  depth, the milestone records that fact and the live demo runs on mainnet —
  the same one code path, only the registry address differs.** No pool is
  assumed to exist; no quote is ever shown for a pair with no pool.

- **M5-R2 — `@flare-kit/contracts` carries the DEX.** A `dex` module exports the
  V2 Router and Factory addresses per network (Coston2 + Flare) and the swappable
  token registry (WFLR/WCFLR, FXRP, USDT0, and any pool-backed token the probe
  finds), plus the minimal V2 ABIs (`getAmountsOut`, `swapExactTokensForTokens`,
  `getPair`, `getReserves`, ERC-20 `allowance`/`approve`). No address is
  hardcoded anywhere else.

- **M5-R3 — `@flare-kit/core` swap operation.** An immutable intent (tokenIn,
  tokenOut, amountIn, slippageBips, deadline, recipient) → a **quote** read from
  live reserves via `getAmountsOut` over an explicit path → an **unsigned plan**
  (an `approve` step only when the allowance is short, then
  `swapExactTokensForTokens` with `amountOutMin` derived from the quote and
  slippage) → **execution** → canonical states, with typed errors distinct for
  no-pool/no-route, insufficient liquidity, slippage-exceeded, and expired
  deadline. It reuses the M1 lifecycle engine and its state table (a reconciler
  walks the table; it never jumps states).

- **M5-R4 — The quote is honest, and slippage is exact.** The displayed quote is
  the real on-chain `getAmountsOut` result; `amountOutMin = quote · (10000 −
  slippageBips) / 10000`, and the surface shows that **minimum received** at full
  precision in the mono face beside the expected out. Price impact is computed
  from the pool reserves and shown. An unknown output renders as `—`, never `0`.
  A quote is re-read on demand and carries the time it was read; a swap submitted
  against a stale quote can still revert on-chain to `amountOutMin`, and that is
  rendered as slippage-exceeded, not as failure of the kit.

- **M5-R5 — Real-first; the mock copies observed behaviour.** The mock swap is
  written only after the real one and reproduces observed reserves, quotes and
  failure shapes (including slippage revert and no-pool). Mock mode is explicit
  and labelled, never a fallback triggered by a failure.

- **M5-R6 — SwapCard.** One currency context (a "you pay" / "you receive" pair
  with a flip), the **Swap** tab active over the real router, and the **Limit**
  tab present as a **declared-unbuilt** state — shown, disabled, and reasoned
  ("no limit-order venue is wired; Uniswap V2 has no native limit order"), per
  DESIGN.md's "a tab that cannot act is not shown" and the fiat-tab precedent.
  Asset marks via `AssetLogo`; exact amounts in mono; the approve and swap steps
  render on the operation spine as the two real steps they are (M5-R8). Follows
  the accepted `swapcard.html`; no new per-surface design artifact.

- **M5-R7 — TokenSelector.** Search, common-base pills, and balance-sorted rows
  each carrying its `AssetLogo`. It offers the kit's known tokens; for the
  *counter* side it surfaces only tokens that have a real pool with the chosen
  side (from the probe/factory), so a person cannot pick a pair the DEX cannot
  quote.

- **M5-R8 — Approvals are never hidden.** The ERC-20 allowance is read; the plan
  includes an `approve` only when it is actually short; and the surface shows
  approve→swap as two distinct steps with their own transactions, never folding
  a silent approval into "Swap".

- **M5-R9 — Network is configuration.** One code path serves Coston2 and mainnet;
  only the registry address changes. Testnet first, mainnet-capable, no source
  rewrite.

- **M5-R10 — Reuse, and one new shared primitive.** Files stay < 300 lines and
  reuse the shared primitives (Button, Panel, AssetLogo, EvidenceChip, the
  operation spine, DataTable for the token rows). The one new shared primitive is
  **`SegmentedTabs`** (the Swap/Limit control), built once in the UI package and
  available to any future two-mode card.

## Out of scope (M5)

- **Limit orders** — no Uniswap V2 primitive exists; the tab is declared-unbuilt,
  not faked. A real limit venue is its own future milestone.
- **Liquidity (add/remove LP), Send, Bridge, Vaults** — later milestones, each
  real-first.
- **V3 / SparkDEX concentrated liquidity** — mainnet-only today, so it fails
  testnet-first; the V2 interface is the committed path. Revisit if SparkDEX
  ships a Coston2 AMM.
- **Path-finding / smart-order-routing** — only explicit single- or two-hop
  paths that `getAmountsOut` can price honestly; the kit never invents a route.

## Acceptance criteria

- **AC1** — A real swap is executed and recorded with its approval tx, swap tx,
  and explorer links, on Coston2 (or mainnet, if R1 finds no testnet depth), with
  the network and addresses noted as evidence.
- **AC2** — The rendered quote equals the on-chain `getAmountsOut` for the same
  inputs; `amountOutMin` is enforced on-chain; a swap that would exceed slippage
  reverts and renders as **slippage-exceeded**, a distinct state, never as
  success or as a kit failure.
- **AC3** — A pair with no pool renders **no route** with a reason, never `0` and
  never a guessed price.
- **AC4** — The approval is shown as its own step; a swap that needed no approval
  shows no approval step.
- **AC5** — Gallery, both themes, states reachable from props: SwapCard {quote,
  needs-approval, approving, swapping, success, no-route, slippage-exceeded,
  Limit-unbuilt} and TokenSelector {search, balance-sorted, no-pool-counter}.
  Computed-style + a11y verified.

## Verification

A live probe script (Coston2, and mainnet for the reference pool) records: router
+ factory code presence, the FXRP-paired pools and their reserves, a real
`getAmountsOut` quote, and a real signed `approve` + `swapExactTokensForTokens`
with tx hashes and explorer links. `pnpm build && pnpm typecheck && pnpm lint &&
pnpm test` green, shown with output. The gallery drives every AC5 state and is
screenshotted in both themes.
