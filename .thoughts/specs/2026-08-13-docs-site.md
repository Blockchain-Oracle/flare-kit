# Spec: flare-kit.xyz — landing page and documentation

Date: 2026-08-13
Status: specified, not built
Governing decisions:
[framework](../decisions/2026-08-13-docs-site-framework.md),
[product name and domains](../decisions/2026-08-03-product-name-and-domains.md),
[full-kit scope](../decisions/2026-08-03-full-flare-application-layer-scope.md)
Design authority: `DESIGN.md`, and the accepted specimens at
`.thoughts/design/fable5-direction-return/` (`index.html`, `docs.html`, `renders/`)

## Objective

Build the site the accepted specimens describe: a landing page at `/` and
documentation under `/docs`. It is a document — full width, the page scrolls.
It is not the application.

## Requirements

- **R1** One Next.js App Router app at `apps/site`. `/` is the landing page,
  `/docs/...` the documentation. (R-SITE-001)
- **R2** Documentation is grouped by consumption depth: Getting started,
  Components, Hooks, Headless, Contracts, Agent Kit. (R-SITE-002)
- **R3** Every component and hook page follows one fixed section order: import
  line, live preview, usage, parameters, return type, states, mock-to-live
  swap. The order is a requirement, not a preference. (R-SITE-003)
- **R4** Every component page carries an interactive preview with a code tab,
  running against `createMockKit()`. No wallet, no chain, no funds. The preview
  is labelled as mock. (R-SITE-004, R-MOCK-004)
- **R5** Every state reachable in `packages/react-ui/gallery/` is reachable on
  the matching docs page, including loading, empty, degraded, partial, error and
  recovery. (R-SITE-005)
- **R6** Preview fixtures are **imported from the gallery**, never re-authored.
  One set of fixtures, one source of truth. Two sets would drift, and the
  gallery's are already browser-verified.
- **R7** The site publishes `/llms.txt` and `/llms-full.txt`, and every page
  offers its markdown source. (R-SITE-006)
- **R8** Search is a Pagefind index built from the output HTML. No server.
  (R-SITE-007)
- **R9** A capability that is planned renders a real page saying what it will be
  and linking the decision that scoped it. Never a dead link, never a page that
  reads as though the thing exists. (R-SITE-010)
- **R10** Where a capability carries a `*Verified` flag in
  `@flare-kit/contracts`, the page shows its real value. A `false` reads as "not
  proven", never as "broken".
- **R11** All copy follows the vocabulary rules in
  `.thoughts/design/2026-08-03-product-surface-map.md` — outcome and progress
  language, protocol vocabulary, authority and privacy language, formatting.
- **R12** WCAG 2.2 AA, verified against computed styles on rendered pages, both
  themes. Status never by colour alone.
- **R13** The landing page shows a real operation with its real anatomy. It does
  not use a three-equal-feature-card layout, and it does not present itself as
  the application.

## The landing page

**Corrected 2026-08-13.** This spec previously recorded a motto —
"Ship Flare operations that recover." — as "already accepted in the specimen."
Abu says he never approved that as a motto; it was only a hero line in one
specimen render. The identity comes from the brand banner
(`brand/flare-kit-banner.svg`): **the developer toolkit for Flare**. The hero
leads with that identity ("The typed toolkit for Flare."), not a slogan. A motto
remains an open choice for Abu; nothing invents or locks one.

The hero pairs the identity headline with a one-line lede, the
`npm create flare-kit-app` line, an honest proof row, and the signature
component (`OperationTimeline`) running live against the mock in the right
column — a genuine lifecycle, including a delayed mint honestly labelled
delayed, not failed.

Sample values are labelled. The specimen labels them `Illustrative`; the built
site runs the actual mock, so its label is `mock kit` and the values are real
mock output rather than fixtures pretending to be live.

## Navigation

| Group | Contents | State |
| --- | --- | --- |
| Getting started | Introduction, Quickstart, Theming, Mock mode | built |
| Components | every component exported by `@flare-kit/react-ui` | built |

[the agent-surfaces decision](../decisions/2026-08-03-agent-facing-surfaces.md);
the pages link it.

## Acceptance criteria

- **AC1** `pnpm build && pnpm typecheck && pnpm lint && pnpm test` green with
  the site in the workspace.
- **AC2** Every component page's preview renders in a browser, in both themes,
  and every state in its switcher is reachable. Verified by screenshot, not by
  typecheck.
- **AC3** Search returns results for a term that appears only in page body text.
- **AC4** `/llms.txt` and `/llms-full.txt` return content, and one page's
  markdown source is retrievable.
- **AC5** Every Agent Kit page states it is planned and links its decision.
- **AC6** axe reports no violations on the landing page and one component page,
  both themes.
- **AC7** No page contains a value that is neither real nor labelled mock.

## Out of scope

- Versioned docs and the version selector (R-SITE-008) — deferred, see the
  framework decision.
- Depending on published packages (R-SITE-009) — blocked until first publish.
- `app.flare-kit.xyz`. Different surface, different spec.
- Hosting and deployment.

## Verification

Drive the site in a browser and screenshot it. Never claim a page is done from a
typecheck. Record the commands and their output.
