## Objective

After this milestone a developer can install the kit and drop a working
**staking** card into their own React app, and:

- a person (or an agent with its own key) can **discover** the live Coston2
  validator set, **read** the on-chain stake minimums (amount, duration) and their
  own P-chain **staked positions** and **mirrored vote power**, then **stake** —
  export native FLR C→P, import to the P-chain, and delegate to a validator with
  `AddPermissionlessDelegator` — a real, value-locking, live-verified operation
  whose success is a **P-chain stake position read back from the chain**; and
- the same developer can **return** the stake after the ≥14-day lock expires
  (P→C export/import) and **claim** the **non-expiring** `ValidatorRewardManager`
  staking reward — each rendered with the value-lock, the lock clock, and the
  reward's distinct (non-expiring) semantics, never collapsed into the delegation
  card's flows.

Staking is the first capability whose signed transaction is **not an EVM/viem
call** — it is a P-chain transaction across a second substrate — and the first
whose primary operation carries a **multi-week irreversible lock** that cannot
close in-session. It reuses the durable, self-reconciling operation lifecycle M1
forced into being and the surface anatomy M5–M10 established, and extends the
project's spine rule — a submitted thing is never a succeeded thing — to a
**P-chain stake-position read** (not the delegate submission).

## The surfaces, and why they differ

- **Staking** is a **value-locking, irreversible, multi-substrate journey.** Where
  M10 delegation was an instantly reversible C-chain relationship, a stake locks
  real FLR on the P-chain for ≥14 days with no early exit. The card must surface
  that irreversibility before signing (the way the rNat 50% burn was surfaced),
  enforce the **live-read** minimums (50k amount / 14-day duration / 365-day max),
  and read the account's stake position back from the P-chain as the source of
  `succeeded`.

- **The staking reward** is a **fourth claim kind** on the existing `ClaimCard`,
  and it is the one that **does not expire.** M10 shipped three kinds (FTSO
  delegation reward with a 25-epoch expiry, rNat, FlareDrop). The staking reward
  is `ValidatorRewardManager` (legacy total/claimed, EVM) — it has **no expiry
  field** and must never share M10's "rewards expire in 25 epochs" line. It is a
  deliberate surface choice (see M11-R6) over the newer FSP `mirror` proof-based
  claim path.

## The honesty it forces

- **A delegate submission is not a stake.** `succeeded` is entered **only** from
  reading the P-chain stake position (`getStakesOf` / `getStakedBalance`) back —
  never from the `delegateOnP` submission. A submitted-but-unconfirmed stake
  renders in-flight.
- **The stake is irreversible for ≥14 days.** The value-lock and the lock clock
  are surfaced as real, non-reversible value commitment **before** signing; the
  return leg is a **delayed, self-reconciling** operation, not a same-session step.
- **The minimums are read live, never hardcoded.** 50k amount, 14-day / 365-day
  duration bounds come from `PChainStakeMirrorVerifier` / `platform.getMinStake` at
  plan time, never from the doc table's mainnet figures.
- **Staking rewards do not expire.** M11 states the `ValidatorRewardManager`
  non-expiry; it never implies the 25-epoch delegation-reward expiry applies here.
- **Validators are live-read, never invented.** The card populates its validator
  set from `platform.getCurrentValidators`; no NodeID literal ships in library
  source, and a stake's `end` cannot exceed the chosen validator's active window.
- **Mirrored vote power is P-chain-sourced and its ABI provenance is labelled.**
  The `PChainStakeMirror` read interface is not a vendored Flare-Foundation ABI;
  where the mirror read is unavailable the position is **declared unavailable, not
  a fabricated zero** (the `mock-never-fills-unobserved` rule, and the M10
  `observed | unavailable` shape).
- **`stakeVerified` gates every write.** It starts `false` and flips `true` only
  after a real broadcast + the confirming stake-position read; until then the
  surface shows the configured path but a declared-unbuilt affordance, never a
  plan. If funding never lands the broadcast **carries declared-unbuilt** and the
  portfolio `stake` placeholder stays declared-unbuilt — the honest collapse-to-B.
- **The shipped runtime stays viem-only.** `@flarenetwork/flare-tx-sdk`/`flarejs`
  is a **devDependency** behind an injected `PChainStakeExecutor` seam — used in
  the live script, tests, and a reference executor — **never imported by shipped
  library source**, exactly as `xrpl` is today.
- **The mock copies only what the live run observed** and refuses the unobserved.

## Requirements

- **M11-R1 — `@flare-kit/contracts` gains the staking registry.** `staking.ts`
  (+ `staking-abis.ts`) carries the `PChainStakeMirror`, `PChainStakeMirrorVerifier`
  and `ValidatorRewardManager` EVM addresses plus the **P-chain network config**
  (the Coston2 P-chain RPC base and `costwo` hrp) as exported constants, and a
  `stakeVerified` flag. EVM addresses are **resolved offline** from
  `FlareContractRegistry.getAllContracts()` and **snapshotted**, verified by a
  parity test — the `ftso/addresses.ts` pattern; no address literal exists outside
  the registry. The validator set is **not** snapshotted (it is live-read, M11-R2).
  The `PChainStakeMirror` ABI is carried minimal + provenance-flagged (not vendored).
  `stakeVerified` starts `false` and flips `true` only after the confirming live
  read, exactly as `delegationVerified` / `gaslessVerified` did.

- **M11-R2 — `@flare-kit/core` stake reads + intent, no flarejs in shipped src.**
  `pchain-rpc.ts` reads the P-chain **without any SDK** (plain JSON-RPC:
  `platform.getCurrentValidators`, `platform.getStake`, `platform.getMinStake`,
  balances). `stake-adapter.ts` reads the EVM side via **viem**
  (`PChainStakeMirrorVerifier` limits, `PChainStakeMirror` mirrored vote power,
  `ValidatorRewardManager.getStateOfRewards`), builds the **stake intent**
  (`{nodeId, amount, startTime, endTime, rewardAddress}`), and defines the
  **`PChainStakeExecutor`** interface (the four signed legs + the reward claim).
  No shipped `packages/*/src` file imports `flare-tx-sdk` / `flarejs`.

- **M11-R3 — the stake lifecycle is durable and self-reconciling.**
  `stake-states.ts` models the four legs (C→P export, P import, delegate, and the
  delayed P→C return) over the **canonical** operation states (no new state id),
  reusing the shared `reconcile.ts` table-walk. The return maps onto the delayed
  shape already forged in M7/M10: `awaiting_external` (the ≥14-day lock clock) →
  `action_required` (unlocked, return claimable) → `succeeded`. A submitted stake
  persists its evidence and reconciles against the P-chain when the app reopens;
  there is no Resume button. `succeeded` is entered only from the on-chain
  stake-position read.

- **M11-R4 — invariants enforced before signing; irreversibility surfaced.**
  `staking.ts` maps intents → a `stakeVerified`-gated plan → the lifecycle, and
  enforces, from the **live-read** limits: amount ≥ `minDelegatorStake`, amount ≤
  `maxStakeAmount`, `minStakeDuration` ≤ (end − start) ≤ `maxStakeDuration`, and
  end ≤ the chosen validator's active `endTime`. The **irreversible ≥14-day
  value-lock** is surfaced as real value commitment before signing. `succeeded`
  is entered only from the on-chain stake-position read.

- **M11-R5 — flarejs is a devDependency behind the executor seam (the `xrpl`
  precedent).** `@flarenetwork/flare-tx-sdk` (+ `flarejs`) is added to
  `packages/core` **devDependencies only**; the shipped runtime keeps its single
  peer (`viem`). The concrete P-chain executor (wrapping `transferToP` /
  `delegateOnP` / `transferToC` / `claimStakingReward`) lives in the live script /
  tests / a reference executor, injected through `PChainStakeExecutor`. `publint`
  and the build confirm no flarejs in the published surface.

- **M11-R6 — staking-reward claim: the fourth, non-expiring kind.**
  `ValidatorRewardManager` (a `GenericRewardManager`) is read via
  `getStateOfRewards(address) → (totalReward, claimedReward)` and claimed via
  `claim(rewardOwner, recipient, amount, wrap)` — **EVM/viem**, **no proof**, **no
  expiry**. It is added as a fourth `ClaimKind` on the existing `ClaimCard`,
  rendered distinctly (reward-type "staking", the non-expiring rule, recipient,
  wrap). It is a **deliberate** choice of the legacy manager the SDK/CLI's
  `claimStakingReward` actually calls, over the newer FSP `mirror` proof-based
  claim through `RewardManager` v2; the spec records the choice and the surface
  never states an expiry.

- **M11-R7 — real-first; the mock copies observed behaviour.** `mock-stake.ts`
  reproduces exactly what the live run(s) observed (the reads, and the stake
  legs/positions if a broadcast lands) and refuses to render anything not
  observed. No live code path constructs a mock under any error.

- **M11-R8 — StakeCard.** One card folding validator discovery, the stake
  composer, the account's stake position + mirrored vote power, and the operation
  timeline. Validator panel: the live-read Coston2 NodeIDs with active windows.
  Composer: amount and duration with the **live-read** min 50k / 14-day / 365-day
  bounds enforced and the irreversible value-lock stated before signing. State
  panel: staked positions + mirrored vote power in the **mono face** with full
  precision. Timeline: the four-leg journey (C→P → delegate → delayed P→C return),
  `succeeded` only from the on-chain read. Reuse `LegTimeline`,
  `OperationTimeline`, `card-chrome`, `Panel`, `Details`/`DetailRow` — never build
  chrome inline.

- **M11-R9 — `@flare-kit/react` hook.** `use-staking.ts` drives the stake
  lifecycle, polling the P-chain stake position and the EVM reward reads. Read/plan
  paths need no key; signing uses the caller-injected `PChainStakeExecutor` (a
  person's wallet or an agent's own key, per the agent-facing-surfaces decision).
  A thin wrapper over the M8 durable-poll hook.

- **M11-R10 — network is configuration; the portfolio `stake` placeholder flips;
  reuse; files < 300 lines.** Addresses/config come from `@flare-kit/contracts`
  (M11-R1); testnet-first, mainnet-capable with no source rewrite.
  `packages/core/src/portfolio.ts` flips its `stake` `UNBUILT_POSITION_TYPES` entry
  to a real **`observed | unavailable`** position (staked positions + mirrored vote
  power) **once `stakeVerified`**; until then it **stays declared-unbuilt**. Reuse
  the shared components — one per pattern. Split any module approaching 300 lines
  before writing. Exact values render in the mono face with asset + full precision.

- **M11-R11 — honesty gates end-to-end.** `stakeVerified` gates every write and
  every position flip; the minimums are live-read; the reward is non-expiring; the
  mirror ABI provenance is labelled and an unavailable mirror read is `unavailable`,
  not a fabricated zero; validators are live-read; and if the broadcast never lands
  (funding), it carries declared-unbuilt with the portfolio `stake` still unbuilt —
  the honest collapse-to-B.

## Out of scope (M11)

- **Governance (R-GOV-001/002/003) → M12.** Proposal discovery/type/state/snapshot,
  vote with vote power, `GovernanceVotePower` delegation,
  `PollingFoundation`/`PollingManagementGroup`, and the mainnet/Songbird-only
  proposal reality. Declared, not dropped.
- **Running a validator (self-bond).** M11 is **delegator** staking only
  (`AddPermissionlessDelegator`). Self-bond needs 1,000,000 FLR / 60-day portal
  rules and a node — its own concern, not built here. Declared, not dropped.
- **The FSP `mirror` proof-based staking-reward claim through `RewardManager` v2.**
  M11 deliberately uses the legacy `ValidatorRewardManager` the SDK/CLI calls
  (M11-R6). The proof-based `mirror` claim is a distinct, later surface.
- **A guaranteed same-session closed round trip.** The ≥14-day lock + 50k floor
  make a closed loop impossible in-window; the return + reward are delayed,
  self-reconciling legs (M11-AC3), the M7 Firelight shape. If 50k funding never
  lands, the broadcast itself carries declared-unbuilt (collapse-to-B).
- **Mainnet staking.** Testnet-first; mainnet addresses/config slot into the same
  registry with no source rewrite when a live run verifies them.
- **Bundling flarejs into the shipped library.** It is a devDependency behind the
  executor seam only (M11-R5).

## Verification

Real-first, on Coston2 (114), reusing the M8/M9/M10 signer
`0xA4b05cdB545FA7CA12Be9f866d64E8A843A31Bd9`. The reads are keyless; the stake
broadcast **needs Abu's go + the signer funded to ≥50,000 C2FLR** (the standard
prior-milestone live-run gate, plus the staking-specific funding floor).

1. **Resolve + snapshot EVM addresses.** Resolve `PChainStakeMirror`,
   `PChainStakeMirrorVerifier`, `ValidatorRewardManager` offline from
   `FlareContractRegistry.getAllContracts()`; snapshot into `staking.ts`; assert
   against the registry in the parity test. Carry the Coston2 P-chain RPC/hrp config.
2. **Keyless reads (M11-AC1).** `probe-stake.mjs`: read the validator set, the
   verifier limits + `getMinStake`, the account stake positions, the mirrored vote
   power and the reward state; confirm the honest empty/observed/unavailable states.
3. **Stake path + invariants (M11-AC2).** Verify the plan gates on the live-read
   limits and surfaces the value-lock; verify the four-leg lifecycle traversal and
   that `succeeded` derives only from the stake-position read.
4. **Live stake broadcast (M11-AC3), gated.** With ≥50k funding + Abu's go:
   `live-stake.mjs` runs C→P export + `AddPermissionlessDelegator` to a live NodeID;
   read the stake position back; flip `stakeVerified`; **carry** the P→C return
   (claimable after the ≥14-day lock) and the reward claim as delayed, self-reconciling
   legs. Without funding: record the reads + the built path and carry the broadcast
   declared-unbuilt (`stake` placeholder stays unbuilt) — no fabrication.
5. Write `mock-stake.ts` from the observed run. Run the full gate and the review gate.

Evidence recorded under `.thoughts/verification/2026-08-12-m11-staking.md`
(+ `coston2-live-stake.json` or the read-probe JSON if the broadcast carries, and
`m11-screens/`), with date, network, addresses, NodeID, transaction ids and
explorer links. **Secrets rule:** signing keys are never logged, printed in
`--json`, or included in evidence.
