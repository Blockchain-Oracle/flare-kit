# M7 Vaults (ERC-4626) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (inline)
> — this milestone is driven **real-first against live Coston2**, so the
> implementer must observe the chain to write correct code and fixtures. Steps use
> checkbox (`- [ ]`) syntax. Plan location follows the project convention
> (`.thoughts/plans/`), overriding the skill default.

**Goal:** Ship real vault deposit + delayed withdrawal (request→wait→claim) to two
live Coston2 ERC-4626 vaults (Firelight, Upshift), as three React surfaces over the
existing M1 operation lifecycle.

**Architecture:** Mirror the M5/M6 stack. `@flare-kit/contracts` gains a
network-keyed `vaults.ts` registry and `vault-abis.ts` (two divergent vault ABIs).
`@flare-kit/core` gains `vault-adapter.ts` (one `VaultAdapter` interface, a
Firelight and an Upshift adapter — the shared thing is the lifecycle, not the ABI),
`vault-quote.ts` (live rate/preview → shares/assets net-of-fee, minimums, position),
and `vault.ts` (immutable intents → unsigned approve-when-short plans → canonical
states, the durable request→wait→claim lifecycle reusing the M1 engine in
`operation.ts`/`states.ts`). The real path is verified live before the mock is
written. `@flare-kit/react-ui` adds `VaultCatalogue`, `DepositCard`, `WithdrawCard`
(each prop-driven with a pure state→chrome split), a `Countdown` primitive, reusing
`SwapLeg`, `PercentPills`, and the `OperationTimeline` spine.

**Tech Stack:** TypeScript, viem, wagmi (peer), React, vitest, Turborepo/pnpm.

## Global Constraints

- Production source files **< 300 lines**; split before writing (CLAUDE.md).
- **Never fake protocol reality**: `submitted` is never rendered as `succeeded`; a
  withdrawal *request* is never rendered as assets received; unknown → `—`, never
  `0`; mock mode is explicit/labelled, never a failure fallback.
- **Reuse, do not re-code**: one shared component per pattern; reuse `SwapLeg`,
  `PercentPills`, `OperationTimeline`, `Panel`/`Button`/`AssetLogo`/`EvidenceChip`/
  `DetailRow`/`Note`/`SourceChip`. Never build a card/badge/pill inline.
- **Network is configuration**: addresses only from `@flare-kit/contracts`
  (`vaults.ts`); no address hardcoded elsewhere. Testnet first, mainnet-capable.
- **Exact values render in the mono face** with tabular numerals, full precision,
  carrying asset + share symbol. `stFXRP`/`vFXRP` are never labelled "FXRP".
- **Operations self-reconcile** against the chain on open; no Resume button.
- **Real integration first**; the mock (`mock-vault.ts`) is written afterwards and
  copies observed behaviour, refusing anything it never observed.
- Gate: `pnpm build && pnpm typecheck && pnpm lint && pnpm test`, shown with output.

### Harness mechanics (read before Task 1)

- **Never `cd` into a package/`sources/`** — the stage guard resolves the project
  root from the shell cwd and will block source writes. Use `pnpm --filter` from
  the repo root.
- **SPEC.md `## Files` manifest** (Task 0, done): a source file must be listed
  there before it is written. The section ends at the next `##`/`###` of any depth.
- **Test lock**: each test file's mtime is compared to SPEC.md's; one SPEC.md write
  unlocks every test file once. Batch test edits behind the one Task-0 SPEC write;
  never touch SPEC.md just to unlock.
- **react-ui imports @flare-kit/react from dist** — a hook/core change needs
  `pnpm build` before react-ui tests see it.
- **`applyTransition` silently drops its patch** on an illegal hop — the reconciler
  must **walk the `states.ts` table** (BFS), never jump states.
- **Signing key**: `.secrets` holds the dev EVM key; live scripts sign with
  `privateKeyToAccount(secrets.evm.privateKey)`. Browser surfaces sign only via
  `onSubmit` and never hold a key. Keys never logged, never in `--json`/evidence.

## Task 2: `@flare-kit/core` — `vault-adapter.ts` (one lifecycle, two ABIs)

**Files:** Create `packages/core/src/vault-adapter.ts`; Test
`packages/core/test/vault-adapter.test.ts`.

**Interfaces — Consumes:** `VaultConfig`, the ABIs, a viem `PublicClient`.
**Produces** the seam every later task depends on — the adapter hides *all*
per-vault ABI divergence behind one shape:
```ts
export interface VaultReads {                       // pure chain reads, no key
  rateAssetsPerShare(): Promise<bigint>             // convertToAssets(1 share unit)
  previewDeposit(assets: bigint): Promise<bigint>   // -> shares
  previewRedeemAssets(shares: bigint): Promise<bigint> // -> assets BEFORE fee
  shareBalance(owner: Address): Promise<bigint>
  assetAllowance(owner: Address): Promise<bigint>   // asset -> vault (deposit)
  shareAllowance(owner: Address): Promise<bigint>   // LP -> vault (upshift withdraw/instant); firelight: n/a
  availability(): Promise<{ paused: boolean; maxDeposit: bigint; maxWithdrawalAmount: bigint }>
  withdrawFeeBips(route: ExitRoute): Promise<number> // instant vs delayed; firelight delayed = 0
  claimable(owner: Address): Promise<ClaimableState> // reconcile a pending request
}
export type ExitRoute = 'delayed' | 'instant'
export type ClaimableState =
  | { kind: 'none' }
  | { kind: 'waiting'; claimableAt: number; ref: ClaimRef }   // unix seconds
  | { kind: 'claimable'; assets: bigint | null; ref: ClaimRef }
export type ClaimRef =                                         // what claim() needs
  | { protocol: 'firelight'; period: bigint }
  | { protocol: 'upshift'; year: number; month: number; day: number }
export interface VaultWrites {                      // build UNSIGNED calldata only
  approveAsset(amount: bigint): UnsignedCall
  approveShare(amount: bigint): UnsignedCall
  deposit(assets: bigint, receiver: Address): UnsignedCall
  requestWithdraw(shares: bigint, receiver: Address, owner: Address, route: ExitRoute): UnsignedCall
  claim(ref: ClaimRef, receiver: Address): UnsignedCall
}
export interface VaultAdapter { reads: VaultReads; writes: VaultWrites; config: VaultConfig }
export function makeVaultAdapter(client: PublicClient, config: VaultConfig): VaultAdapter
```
`UnsignedCall` is the existing core type M5/M6 use (`{ to, data, value? }` shape —
reuse it, do not invent a new one).

**Non-obvious adapter behaviour to encode (from the probe):**
- Firelight: `share.kind==='self'` → `shareAllowance` is n/a (the vault burns its own
  shares; no approve needed for redeem). `claimable` reads `currentPeriod`,
  `withdrawalsOf(period,owner)` and `isWithdrawClaimed`; a request made in period P is
  claimable after that period ends, so `claimableAt = currentPeriodEnd` when
  `currentPeriod === P` else already claimable. `requestWithdraw` route is always
  `delayed`; calling it emits `redeem(shares, receiver, owner)`.
- Upshift: `share.kind==='lp'` → withdraw/instant **pull the LP token**, so
  `shareAllowance` and `approveShare` are real. `requestWithdraw` dispatches on route:
  `instant` → `instantRedeem(shares, receiver, owner)` (immediate, `instantRedemptionFee`);
  `delayed` → `requestRedeem(...)` then `claim(year,month,day,receiver)` after
  `lagDuration`. `claimable` uses `getWithdrawalEpoch` + the pending-redemption read.
  `withdrawFeeBips('instant')` = `instantRedemptionFee`, `('delayed')` = `withdrawalFee`.
- Both fee values are raw contract units — record the exact scaling observed in Task 5
  and convert to bips in ONE place here; never guess the scale.

- [ ] **Step 1** Write `vault-adapter.test.ts` against a mocked `PublicClient` that
  returns the probe values: assert Firelight `shareAllowance` is n/a / 0-path,
  Upshift dispatches `instant`→`instantRedeem` and `delayed`→`requestRedeem` (assert
  the encoded selector), and `claimable` maps `currentPeriod`/epoch → `claimableAt`.
- [ ] **Step 2** Run `pnpm --filter @flare-kit/core test vault-adapter` — expect FAIL.
- [ ] **Step 3** Implement `vault-adapter.ts` (< 300 lines; if it exceeds, split the
  two adapters into `vault-adapter-firelight.ts`/`vault-adapter-upshift.ts` behind
  the factory).
- [ ] **Step 4** Run the test — expect PASS.
- [ ] **Step 5** Commit `feat(core): VaultAdapter — one lifecycle over two vault ABIs`.

**Acceptance:** every per-vault ABI difference lives behind the adapter; no later
file references a raw vault ABI; the selector-dispatch for Upshift routes is tested.

## Task 3: `@flare-kit/core` — `vault-quote.ts` (honest quote, position, minimums)

**Files:** Create `packages/core/src/vault-quote.ts`; Test
`packages/core/test/vault-quote.test.ts` (fixtures = probe values, then Task-5
measured values).

**Interfaces — Consumes** `VaultAdapter`. **Produces:**
```ts
export interface DepositQuote {
  assetsIn: bigint; expectedShares: bigint; minShares: bigint   // min = expected*(1e4-bips)/1e4
  rate: bigint; readAt: number; asset: TokenMeta; share: TokenMeta
}
export interface WithdrawQuote {
  shares: bigint; route: ExitRoute; feeBips: number
  expectedAssets: bigint; minAssets: bigint; readAt: number; asset: TokenMeta; share: TokenMeta
}
export interface VaultPosition {
  shares: bigint; assetsValue: bigint | null                    // convertToAssets(shares); null if read failed
  pending: ClaimableState; asset: TokenMeta; share: TokenMeta
}
export function quoteDeposit(a: VaultAdapter, assetsIn: bigint, slippageBips: number): Promise<DepositQuote>
export function quoteWithdraw(a: VaultAdapter, shares: bigint, route: ExitRoute, slippageBips: number): Promise<WithdrawQuote>
export function readPosition(a: VaultAdapter, owner: Address): Promise<VaultPosition>
```

**Honest-rendering rules to encode:**
- Unknown/failed read → the field is `null` and renders `—`; never `0`.
- `expectedAssets` is **net of `feeBips`** — the fee is applied here so the surface
  shows the real received amount, and instant vs delayed differ only by their fee.
- `readPosition` never invents a "no position": a failed `shareBalance` read →
  `assetsValue: null` and the surface shows *unavailable* (the M6 F1 rule); a
  genuine `0` share balance is a real *no-position*.
- `minShares`/`minAssets` at full precision, mono; a live rate move that later trips
  the on-chain minimum is a distinct `share/slippage-exceeded` state (Task 4), not
  computed as failure here.

- [ ] **Step 1** Write `vault-quote.test.ts` with the probe fixtures (1:1 Firelight
  rate → `quoteDeposit(1e6, 50)` gives `expectedShares 1e6`, `minShares 995000`);
  Upshift `quoteWithdraw` net-of-fee for both routes; `readPosition` `null` on a
  throwing `shareBalance`.
- [ ] **Step 2** Run — expect FAIL. **Step 3** Implement (< 300 lines; split at the
  quote/position seam if needed). **Step 4** Run — expect PASS.

## Task 4: `@flare-kit/core` — `vault.ts` (intents → plan → durable lifecycle)

**Files:** Create `packages/core/src/vault.ts`; Modify `packages/core/src/index.ts`;
Test `packages/core/test/vault.test.ts`, `packages/core/test/vault-states.test.ts`.

**Interfaces — Consumes** adapter + quote + the M1 engine (`operation.ts`,
`states.ts`). **Produces:**
```ts
export interface DepositIntent { readonly vaultKey: string; readonly network: FlareNetworkKey
  readonly assetsIn: bigint; readonly slippageBips: number; readonly deadline: number; readonly recipient: Address }
export interface WithdrawIntent { readonly vaultKey: string; readonly network: FlareNetworkKey
  readonly shares: bigint; readonly route: ExitRoute; readonly slippageBips: number
  readonly deadline: number; readonly recipient: Address }
export type VaultPlan = { steps: PlanStep[] }        // reuse the M5/M6 PlanStep union
export function buildDepositPlan(a, intent, owner): Promise<Result<VaultPlan, VaultError>>
export function buildWithdrawPlan(a, intent, owner): Promise<Result<VaultPlan, VaultError>>
export function buildClaimPlan(a, ref, recipient): Promise<Result<VaultPlan, VaultError>>
export type VaultError =
  | { kind: 'paused' } | { kind: 'cap-exceeded'; max: bigint } | { kind: 'insufficient-balance' }
  | { kind: 'share-slippage-exceeded' } | { kind: 'expired-deadline' } | { kind: 'not-verified' }
export type VaultState =                              // canonical operation states
  | 'pre-plan' | 'needs-approval' | 'approving' | 'submitting'
  | 'requested' | 'waiting' | 'claimable' | 'claiming' | 'concluded'
  | 'instant-concluded' | 'paused' | 'cap-exceeded' | 'insufficient-balance'
  | 'slippage-exceeded' | 'expired' | 'not-verified'
```

**Lifecycle rules (the load-bearing part):**
- The **states.ts transition table** is extended with the vault withdraw path:
  `submitting → requested → waiting → claimable → claiming → concluded`, and the
  instant path `submitting → instant-concluded`. Deposit path:
  `pre-plan → [needs-approval → approving] → submitting → concluded`.
- `buildWithdrawPlan` **refuses** (`{kind:'not-verified'}`) when the vault's
  `withdrawVerified === false` for the intent's network — never emits a plan that
  could misrender/revert (M7-R10 / the M6 F2 precedent). Deposit is allowed on any
  network where `previewDeposit` reads (standard ERC-4626).
- Reconciliation walks the table via BFS (never `applyTransition` jumps) and derives
  `waiting` vs `claimable` from `adapter.reads.claimable(owner)` on app open —
  chain state, not session state.
- `paused`/`cap-exceeded` are produced from `availability()` before any signature.

- [ ] **Step 1** Write `vault-states.test.ts`: assert the withdraw table has no
  illegal hop that would silently drop a patch (reuse the M6 table-walk test shape);
  assert `buildWithdrawPlan` on a `withdrawVerified:false` vault returns
  `not-verified` and emits **no** approval step.
- [ ] **Step 2** Write `vault.test.ts`: deposit plan approve-when-short (0/1 approval);
  paused → `paused`; assetsIn > maxDeposit → `cap-exceeded`; expired deadline → `expired`.
- [ ] **Step 3** Run — expect FAIL. **Step 4** Implement `vault.ts` + extend
