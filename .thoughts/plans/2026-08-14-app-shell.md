# App shell implementation plan (`apps/app`, plan 1 of N)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up `app.flare-kit.xyz` as a working, navigable, network-aware shell — rail, top bar, routing, and honestly declared-unbuilt seams — with no operations wired yet.

**Architecture:** A Next 16 App Router app in `apps/app`, wearing the kit's token contract exactly as `apps/site` does (`.fk` on `<body>`, no tokens of its own). The rail is driven by one `FAMILIES` registry so navigation, routing and the unbuilt seams cannot disagree. Unlike the docs site, the app is a fixed panel: the page never scrolls, the panel scrolls internally.

**Tech Stack:** Next 16 (App Router), React 19, TypeScript, vitest + jsdom + @testing-library/react, `@flarekit-dev/{contracts,core,react,react-ui}` as workspace deps.

**Spec:** `.thoughts/specs/2026-08-14-app-surface.md` (accepted by Abu, 2026-08-14)

## Global Constraints

- Production source files stay under **300 lines**. Split before writing.
- The app declares **no `--fk-*` token of its own** and defines no card, badge, pill, chip or spine. It assembles `@flarekit-dev/react-ui`. A missing pattern is added to that package, not to a screen.
- Addresses and chain data come from `@flarekit-dev/contracts`. **No literal address, chain id or RPC URL anywhere in this app.**
- Networks are exactly two: `coston2` and `flare`. `FlareNetworkKey = 'coston2' | 'flare'`, `FLARE_NETWORKS`, `chainFor(chainId)` are the existing exports.
- **No mock mode.** No mock entry in the network selector, no mock fallback, ever.
- The app holds **no signing key**. There is no server-side signing path.
- An unsupported or unbuilt capability is **shown and disabled with its reason stated**, never hidden and never given a fake preview.
- Exact values render in the mono face with full precision.
- Gate before every commit: `pnpm build && pnpm typecheck && pnpm lint && pnpm test` from the repo root.
- Never claim UI works from a typecheck. Drive it in a browser, screenshot it, look at the screenshot.

## Decisions taken under Abu's standing "follow your recommendation"

- The rail is **flat** — no groups — until it demonstrably hurts.
- The app **lands on Swap**, matching the mockup Abu chose and Uniswap muscle memory.

```ts
import { type FlareNetworkKey, FLARE_NETWORKS } from '@flarekit-dev/contracts'

/**
 * Exactly the networks the protocol has. There is no Mock entry: mock mode is a
 * documentation surface, and this app connects to a real network or shows
 * nothing. An unrecognised stored value falls back to testnet rather than
 * throwing — a corrupt preference must not brick the app — but it never falls
 * back to something that is not a chain.
 */
export const SELECTABLE_NETWORKS = Object.keys(FLARE_NETWORKS) as readonly FlareNetworkKey[]

export const NETWORK_STORAGE_KEY = 'flare-kit:app:network:v1'

const DEFAULT_NETWORK: FlareNetworkKey = 'coston2'

export function readStoredNetwork(storage: Pick<Storage, 'getItem'>): FlareNetworkKey {
  const stored = storage.getItem(NETWORK_STORAGE_KEY)
  return stored !== null && (SELECTABLE_NETWORKS as string[]).includes(stored)
    ? (stored as FlareNetworkKey)
    : DEFAULT_NETWORK
}

export function storeNetwork(storage: Pick<Storage, 'setItem'>, key: FlareNetworkKey): void {
  storage.setItem(NETWORK_STORAGE_KEY, key)
}
```

If `Object.keys(FLARE_NETWORKS)` does not come out `['coston2', 'flare']` in that order, read `packages/contracts/src/chains.ts` and write the order explicitly rather than changing the test.

`apps/app/components/rail.tsx`:

```tsx
import Link from 'next/link'
import { FAMILIES } from '../lib/families'

/**
 * The persistent rail. Flat, no groups — eleven-plus families fit, and grouping
 * is a decision to take when it demonstrably hurts rather than in advance.
 *
 * An unbuilt family is LISTED and reachable. Hiding it would present the app's
 * shape as the protocol's shape, and the whole product is about not doing that.
 */
export function Rail({ currentId }: { currentId: string }) {
  return (
    <nav className="app-rail" aria-label="Capabilities">
      <ul>
        {FAMILIES.map((family) => {
          const unbuilt = family.status.kind === 'unbuilt'
          const describedBy = unbuilt ? `rail-note-${family.id}` : undefined
          return (
            <li key={family.id}>
              <Link
                href={`/${family.id}`}
                className="app-rail-link"
                aria-current={family.id === currentId ? 'page' : undefined}
                aria-describedby={describedBy}
                data-unbuilt={unbuilt ? 'true' : undefined}
              >
                {family.label}
              </Link>
              {unbuilt && (
                <span id={describedBy} hidden>
                  Not built yet
                </span>
              )}
            </li>
          )
        })}
      </ul>
    </nav>
  )
}
```

```tsx
import type { Family } from '../lib/families'

/**
 * A reserved seam, stated. It names the capability, says it is not built, and
 * names the milestone that owns it — and it renders NO preview, because a
 * fabricated preview of an unbuilt capability is the same lie as a fabricated
 * balance.

export function Unbuilt({ family }: { family: Family }) {
  if (family.status.kind !== 'unbuilt') return null
  return (
    <section className="app-unbuilt">
      <h1>{family.label}</h1>
      <p className="app-unbuilt-state">Not built yet.</p>
      <p>{family.status.will}</p>
      <p className="mono app-unbuilt-owner">{family.status.milestone}</p>
    </section>
  )
}
```
