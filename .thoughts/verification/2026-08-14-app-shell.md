## What the screenshots caught that the gate did not

Every automated check was green when the first screenshot was taken. Looking at
it found five defects:

1. **R-APP-001 violation** — no divider above the reserved seams, so `Chat`,
   `Confidential compute` and `Operator release` read as ordinary capabilities.
2. **CLAUDE.md violation** — the unbuilt panel was a hand-rolled `<section>`
   rather than the kit's `Panel`.
3. The network selector was raw browser chrome, unstyled and jammed against its
   label.
4. No brand identity in the rail at all.
5. `/favicon.ico` 404 on every load.

All five fixed in `17488ea` and `15973ad`, and re-verified in the browser.

## Two defects found in the fixing

- **`hidden` was the wrong mechanism** for the rail's unbuilt note. A hidden
  element is dropped from the accessibility tree in some user agents, so the
  description existed for exactly one reader and was invisible to them. Now the
  kit's own `.fk-sr` — "only ever announced, never drawn" — which already
  existed.
- **`toHaveAccessibleDescription` did not fail, it HUNG.** One assertion took
  the app suite from under two seconds to **fifteen minutes**, and the first
  symptom was a 600s gate timeout that looked like infrastructure. Replaced with
  assertions through the description's own element, which are stricter (they pin
  that the note is reachable *and* that it is not `hidden`) and run in
  milliseconds.
