## Load-bearing discoveries (real-first caught all three; a mock never would)

1. **Upshift's `deposit` is non-standard** — `deposit(address assetIn, uint256
   amountIn, address receiver)`, asset-address-first, and its previews return two
   values including a contract-computed `assetsAfterFee`. The standard ERC-4626
   `deposit(uint256,address)` selector would hit the wrong function. The kit renders
   `assetsAfterFee` (contract-computed) as the honest received amount per route.
2. **Firelight's `maxDeposit` hides a custom GLOBAL `depositLimit`.** `maxDeposit`
   returned `uint256` max, but a 1 FXRP deposit reverted `DepositLimitExceeded()`
   (`0x6adf7e28`): `depositLimit` 15.000000, `totalAssets` 14.994061 → only
   **0.005939 FXRP of real headroom**. The adapter now reads `depositLimit` /
   `totalAssets` and caps availability at the true headroom; a deposit over it
   renders `cap_exceeded`, never a revert after approval.
3. **The mainnet Upshift share is `earnXRP`, not testnet's `vFXRP`** (Flare block
   67172499). The probe read it rather than guessing, so the registry is honest.
4. **The withdraw wait needs no new lifecycle state** — it maps onto the existing
   canonical `awaiting_external` (period/epoch clock) → `action_required`
   (claimable) → `succeeded`, the same shape M3's FDC proof uses. A withdrawal
   *request* structurally cannot render as assets received.
5. **Gas must be buffered on the first period request.** Firelight's first `redeem`
   in a period does extra checkpoint writes; a gas estimate taken right after the
   deposit undercounted and the tx went out-of-gas (the tx replayed fine via
   `eth_call`, confirming it was gas, not logic). The live script buffers gas 1.5×.

### Two defects the browser drive caught that jsdom could not

1. **PercentPills computed to `min-height:0; padding:0` (21px, unstyled) inside `WithdrawCard`.**
   Its M6 CSS was scoped `.fk-liq .fk-pct*`, but the vault card's root is `.fk-vault-card`, so the
   pills got no styling and failed the 24px target size. PercentPills is now a shared primitive
   (M6 + M7), so its CSS was broadened to the kit root `.fk .fk-pct*` — M6's layout unchanged
   (same rules, wider scope), vault pills now 31.5px. The jsdom tests passed throughout; only the
   real render exposed it.
2. **The gallery fixture jumped `executing → succeeded` (an illegal hop).** `applyTransition`
   silently drops the patch, so the "claimed" and "instant-success" cards were stuck rendering

   uses); both now render "Withdrawn"/"Redeemed". This is the exact `applyTransition` hazard the
   project already documents — a product-correct render logic, exposed only by a real state walk.

## Review gate — three reviewers, real honesty bugs found and fixed

Correctness, honest-rendering/silent-failure, and simplification reviewers ran over the M7
diff. Correctness and silent-failure **independently converged** on the same load-bearing
defects in the shared read layer (`vault-adapter.ts`), where a zero read was promoted to a
confident terminal conclusion — the exact anti-pattern the M6 F1 lesson warns against. All
fixed before close, each with a new test (the false-success paths were previously uncovered):

- **CRITICAL — Upshift `claimable` had no clock guard.** `claimed: burnable === 0n`; during the
  ~1-day wait `getBurnableAmountByReceiver` is 0, so a still-waiting withdrawal self-reconciled
  to `succeeded` → "Withdrawn" while nothing had moved (fires on every app reopen during the
  wait). Fixed: thread `now`; before the epoch a 0 burnable is WAITING (`assets: null`), only
  after the epoch does a 0 burnable mean claimed — mirroring Firelight's currentPeriod guard.
- **IMPORTANT — Firelight `availability` fabricated a pause.** `depositPaused: effectiveMax === 0n`
  rendered a FULL vault (headroom 0 — one 0.006 FXRP deposit away today) as "Deposits paused", a
  halt the chain never signalled, and masked the accurate `cap_exceeded`. Fixed: `depositPaused`
  is only ever a real read; a full vault flows through `cap_exceeded` (`maxDeposit: 0`).
- **IMPORTANT — Firelight `claimable` conflated `withdrawalsOf === 0n` with claimed.** Fixed:
  `claimed` comes from `isWithdrawClaimed` alone; a zero recorded amount while unclaimed is
  unknown (`assets: null`, still claimable), never a false success.
- **Minors, addressed:** the `feeLabel`/`feesLabel` duplication is homed as one `feeBipsLabel` in
  `card-chrome.ts` (which also fixes an instant-0-fee rendering "0.00%" while delayed-0 read
  "None"); the unused `requesting`/`claiming` `TimelinePhase` variants dropped; the `availability`
  no-pause `false`s now carry ABI-citing comments; the mock's demo-convenience wallet balance is
  documented as distinct from the protocol reads' refuse-the-unobserved discipline. The mock
  config knobs the simplifier flagged as unused are now each **test-driven** (paused/cap/waiting
  gates), turning speculative config into tested honesty behaviour.
