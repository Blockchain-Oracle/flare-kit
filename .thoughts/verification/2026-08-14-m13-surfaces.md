## Every state, and where it comes from

No state is hand-written. Plans come from the real `planInstruction`, catalogues from the
real `buildInstructionCatalogue`, lifecycles from the real `reconcileInstruction` fed the
observations the live runs produced, and history actions are decoded by the real
`decodePaymentReference`.

- **SmartAccountCard** — both networks side by side (identical address **compared**, not
  claimed); undeployed with observed zeroes; funded-but-undeployed; a partial read (`—`
  beside real values, deployment `unknown` and never "no"); everything unread; history
  listed; history confirmed-empty; history unavailable.
- **InstructionCatalogue** — Coston2 live (8 available, 3 superseded); Flare mainnet showing
  the fee divergence the no-fallback rule exists for (950 000 for five ids against a 500 000
  default); all-unknown; not-served-here; loading.
- **InstructionComposer** — the full chain before approval; the deposit plan against
  controller vault 1; the mainnet `unverified` gate as a declared-unbuilt affordance;
  `recipient_unfunded`; the four in-flight legs; `succeeded`; succeeded-dispatched-by-another;
  proof-expired; and in-flight-while-nothing-is-watching.

Two cases are driven from something other than a live read and say so on the case label: the
`unavailable` reads (a read that did not land — a failure state, not invented protocol data),
and the catalogue's `Not served here` row, which **no** observed deployment produces because
both networks register vaults of both types. That one is driven from a controller with an
empty vault registry, because the state has to be visible to be checked.

## Defects found by looking at the rendered screens

Five, all fixed and re-verified. Four of them a typecheck could never have caught.

1. **The a11y regression I introduced.** `.fk-sa-compose[data-op-state='expired'] .fk-sa-chain`
   faded the plan to `opacity: 0.72`; the audit measured five elements inside it falling to
   **3.00:1** against a 4.5:1 requirement — the plan a person most needs to read carefully,
   made hardest to read, in the one state where their money is already gone. The rule is
   deleted. Deadness is carried by the terminal note and the absent affordance.
2. **`RecoveryPanel` told an expired operation it was safe.** `expired` is deliberately
   **not** in the canonical terminal set (an expired *quote* is re-quotable, and that is right
   for swaps and bridges), so an expired instruction fell through to *"this operation is
   progressing on its own… nothing is at risk while it completes."* Nothing was progressing
   and the XRP was already the operator's. The panel now returns `null` for `expired`; the
   canonical table is untouched.
3. **The countdown read `Ready` on a dead operation.** `Countdown` clamps to that word at
   zero — correct for a matured withdrawal, actively misleading beside copy saying the proof
   can never be used. The expired state now shows the instant in past tense and no countdown.
4. **Numbers broke across two lines.** In a side-by-side column, `.fk-row-v`'s
   `overflow-wrap: anywhere` split `0.000000000000000000` down the middle. A number in two
   pieces is not an exact value. Fixed with a container query (the first in this package —
   the column's width is set by the host, so a viewport media query would measure the wrong
   element) that stacks label above value below 340px.
5. **The availability chip was clipped.** `collateralReservationAndDeposit` is one
   31-character unbreakable token and became the column's 263px floor, pushing the table 24px
   past its container and cutting the chip that carries the row's answer. The identifier is
   allowed to wrap; the chip is not allowed to be cut.

Two legibility fixes came from the same pass: the controller-vault-namespace warning was
repeating under all eight vault rows and now appears once, and an unreadable controller's
identical reason on all eleven rows now appears once (`sharedReasonOf`, which keeps per-row
reasons whenever they genuinely differ — asserted both ways).

## Changes outside the three surfaces

- **`instructionSpine()` exported from `smart-accounts/states.ts`.** The reconciler indexes
  off `record.steps.length` (`n-3`, `n-2`, `n-1`), so the four legs and their order were
  already a contract held only by a test fixture's private copy. It is now one shipped
  builder; the fixture delegates to it, so a record with three steps can no longer reconcile
  a leg behind for its whole life with nothing to catch it.
- **`mockInstructionRecord()`** added to the mock and used by both the gallery and the test
  fixture — one builder that walks the full legal path and throws if it did not arrive.
- **`mock-smart-accounts.ts` split** into a record (`mock-smart-accounts-observed.ts`) and a
  reader, when the two together crossed 300 lines. The public surface is unchanged (the
  reader re-exports the record).
- **Mainnet read-lens values added to the mock** from the 2026-08-13 probe, so the
  identical-address property can be shown from two independently-read values rather than one
  value printed twice. `smartAccountsVerified.flare` stays `false` and planning against it
  still returns the real `unverified` refusal — asserted.
- **`InstructionChain.tsx` split from `InstructionComposer.tsx`** at 320 lines. The seam is
  real, not arithmetic: the chain renders a **plan** (what will happen), the composer renders
  an **operation** (what did). Keeping those apart is what this milestone spends its effort on.

## The review gate (M13-AC7)

Four reviewers over `05c51f5..HEAD`: correctness, honest-rendering/silent-failure,
simplification, test-quality. **No Critical findings in the shipped code.** Everything
Important is fixed below; the Criticals that were raised were all against the *tests*, not
the product — which is its own finding about how much a green suite was worth here.

**Honest rendering — 4 Important, fixed:**

1. **`paused` was rendered and never read.** The card said "Dispatch · Open" on both networks;
   no script called `isPaused` and the word appears in neither evidence file. Coston2 was at
   least corroborated by a dispatch that succeeded — mainnet by nothing. Rather than soften
   the card, `scripts/verify-smart-account-evidence.mjs` (keyless, read-only) now reads it on
   both networks. Same pass sourced the `xrplLedgerIndex` values and re-read the deposit's
   dispatch identifiers, which had been hand-authored into the live evidence (the round-second
   timestamp was the tell). Every value matched what the mock already carried. Recorded in
   `2026-08-14-m13-evidence-backfill.json`.
2. **An empty operator-wallet list rendered `—`.** A successful read finding no wallet is a
   deployment gap the planner refuses by name (`no_operator_wallet`); `—` said "we could not
   look". Now "None registered", matching the vault row two lines below it.
3. **A never-attempted catalogue read rendered as an empty table** — a claim that the
   deployment serves nothing. Now an `EmptyRow` saying so.
4. **`smartAccountPosition` conflated unverified with unavailable.** `unavailable` means "the
   read did not land" everywhere else in `portfolio.ts`; using it for an unproven network
   blamed the network for a gap in what the kit has proven. New `unbuilt` status.

Also fixed from its Minors: the mock's `blockTimestamp` was dispatch-time-minus-two-minutes
under a comment calling it the ledger close — it is now the **real** close, read back off the
XRP Ledger; and the gallery's deposit plan was built against the pre-run-1 account, so the
composer claimed that instruction would deploy the account and that it did not exist yet, both
false of that run (`OBSERVED_ACCOUNT_AFTER_TRANSFER` now records the real between-runs state).

**Simplification — 2 Important, fixed:** `smartAccountPosition` had **no production caller**,
so the portfolio had neither an unbuilt declaration nor an observed position — now exposed by
`useSmartAccount`. And the spine moved onto `InstructionPlan`, matching `staking`,
`delegation`, `governance` and `rewards`, so a host holding a plan cannot hand-write a
three-step spine that reconciles a leg behind for the operation's life. It pushed back on two
choices and both were kept: three `*-state.ts` files should stay three, and `sharedReasonOf`
cannot hide a genuinely per-row reason.

**Test quality — the most useful pass.** Two reviewers independently found that **three of the
new assertions could not fail**:

- `expect(text).toContain('0 drops')` — the file's headline claim — passed off the *default
  instruction fee* row, because `"1000 drops"` contains `"0 drops"`. The rule it was named
  for ("an unread value is never a zero") had no falsifiable coverage in either direction.
- `expect(querySelectorAll('.fk-sa-row-reason').length).toBeGreaterThan(0)` — that class is
  also on the vault-id spans, which render regardless, so the dedupe mutant survived.
- `[...querySelectorAll('button')].every(b => b.disabled)` — `[].every()` is `true`, so
  deleting the action block entirely would have passed.

All three are now exact-equality assertions scoped to the row or the specific control, and
each was **mutation-checked**: collapsing an observed `0n` into `—`, dropping the dedupe
guard, enabling the CTA on a refusal, and relaxing the parity guard to `length < 1` each now
fail a named test. Nine further untested states were covered — the non-`unverified` refusal
path (the highest-harm gap: an enabled "Sign the XRPL payment" on a plan the controller
rejects), plan warnings reaching the screen, the `onSelect` availability gate, a populated
history including a dispatch the codec could not parse, the read mainnet per-id fee,
`dispatchedByUs === true`, the pinned-executor tri-state, single-network parity, and partial
reads.

Two source fixes came out of it: `OperationTimeline` now forwards `nowMs` to `RecoveryPanel`,
which was falling back to `Date.now()` and quietly re-introducing a wall clock into surfaces
that take `now` as a prop precisely so screenshots are deterministic; and a pre-existing
assertion comparing a dispatcher *address* to a transaction *hash* (never equal, so always
true) was replaced.

`packages/react` had **no smart-account hook tests at all** — `use-smart-account.test.tsx` now
covers the seam where `smartAccountsVerified` is threaded into the position, which is what
makes mainnet report `unbuilt` rather than a position read off an unproven path.
